# pcbview change requests

Changes this project needs from pcbview (pinned at `vendor/pcbview`). Each is
worked around here with data only; fixes land in pcbview's repo, then the pin
is bumped.

## 1. `models` should check that a stand-in's file exists

**Seen:** 2026-11-03, pin 4e9dfa2. A `[models."USB-C_SMD-TYPE-C-31-M-12_1.wrl"]`
stand-in pointing at `${KICAD9_3DMODEL_DIR}/Connector_USB.3dshapes/USB_C_Receptacle_HRO_TYPE-C-31-M-12.step`
was reported by `pcbview models` as `substituted` (looks fine), but that file is
not in this machine's KiCad 9 install. The build then boxed J1 with
"kicad-cli could not load it", which reads like a broken STEP, not a wrong path.

**Want:** `models` (and the build's `why`) to report a substituted path that
does not exist as `missing: stand-in path not found: <expanded path>`, the same
way it already does for a footprint's own path.

**Workaround:** the stand-in names the same model from the kicad-demos package
(`/usr/share/kicad/demos/royalblue54L_feather/lib/3dmodels/...STEP`).

## 2. Re-embed without rebuilding

**Why:** this project's `embed` page (`out/index.html`) is regenerated by
`scripts/render.py` much more often than the viewer is rebuilt, and a fresh page
has empty markers. Today render.py copies the block pcbview last wrote from the
old page into the new one; if the old page is ever lost, the dashboard shows
"no viewer built yet" until a full `build` (or `--only` a stage) runs again.

**Want:** a cheap command that only rewrites the embed blocks from the site
already in `out`, e.g. `pcbview embed pcbview.toml [--board ID]`, so a page
generator can call it after writing its page.

**Workaround:** render.py's `_viewer_block` carries the old block over.

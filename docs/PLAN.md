## Current state (as of commit `3d8585f`, Aug 2026)

Converging, DRC-clean (0 errors / 0 unconnected; silk warnings only) build
of a Ø30.5mm teardrop earring: RP2354A (QFN-60) front, LIR2032 + clip
back, 37 addressable LEDs (TBA-C1010MB, 34 on the perimeter at ~2.40mm
pitch + 3-LED tip chevron matching that density), USB-C at the tip
(hand-routed locked differential pair), MSK12C02 power slide switch,
NCP730 LDO, load switch, charger. 4-layer JLC04161H-7628, all LCSC parts.

- `design.yaml` is the single source of truth; `python3 build.py` runs
  board → place → preview → route (freerouting, retried up to 6x with
  finish) → finish → drc → render → export.
- The last full build converged on attempt 1 in ~2.5 min.

## The dashboard (plan-of-record review surface)

- `out/index.html` is **generated by scripts/render.py** every build:
  placement previews, routed raytraces, layout top/bottom PNGs, a 2x2
  copper-layer grid, the layer stack widget (radio = opaque layer,
  checkboxes = visibility, slider = others' opacity), and an interactive
  3D board (three.js r160 + TrackballControls for continuous tumbling,
  loading `out/board.glb`). Auto-refreshes every 15 s.
- Serve with: `cd out && python3 -m http.server 8618 --bind 0.0.0.0`
  (usually already running — check `ss -tlnp | grep 8618`).
- three.js is vendored in `web/vendor/` (copied to `out/vendor/` each
  render). Never switch to CDN script tags.

## Adding the IMU — task breakdown

1. **Part selection.** Want: LGA, I2C, 1.71–3.6 V, wake-on-motion
   interrupt, tiny, JLC-assemblable/LCSC-stocked. Default recommendation:
   **ST LSM6DS3TR-C** (6-axis, LGA-14 2.5×3.0×0.83 mm, ubiquitous at
   JLC). Lower-power accel-only alternative: LIS2DW12 (LGA-12 2×2 mm).
   Look up the live LCSC part number / stock before committing; put it in
   `bom/parts.yaml` like the other parts.
2. **Footprint + 3D model.** Source via easyeda2kicad into
   `library/parts.pretty` / `library/3d/ee.3dshapes` like the rest.
   *Check the 3D model offset against the footprint anchors* by parsing
   the WRL point cloud (pegs/pins vs pad positions) — easyeda2kicad
   offsets have been wrong by 1.5–2.3 mm twice on this board. If a .step
   ships with it and misplaces in the GLB, rename it `.step.disabled`
   so `--subst-models` falls back to the WRL (see `git log 79b5450`).
   If no model exists, write a WRL box from datasheet dimensions like
   `library/3d/ee.3dshapes/LED_TBA-C1010MB.wrl` (translucent grey,
   VRML unit = 0.1 inch, transform baked in the file, footprint offset 0).
3. **circuit.py.** Add `U6` (IMU), a 100n decap on 3V3 tight to its VDD
   (+ 100n on VDDIO if the part splits rails), I2C pull-ups 2×4.7k to
   3V3, `IMU_INT1` to a free GPIO. RP2354A has plenty of free GPIOs
   (LED data, VBSENSE/GPIO29, BOOTSEL, PWR_EN, SWD are taken; check
   `circuit.py` pin map). Use an I2C-capable pin pair (any GPIOs work
   for I2C0/I2C1 per RP2350 pin mux rules).
4. **place.py.** Candidate zones (verify against the placement preview,
   nothing else lives there): front lower-left near D1/the CHRG LED
   (~(−6.5, −4.5)) or front right of C13/U4 (~(6.5, 0.5)). Constraints
   that bite (all enforced by DRC/finish, but knowing them saves loops):
   - keep ≥1.4 mm between any new pads and the QFN pad rows (escape
     channels; traces need 0.404 mm),
   - the LED bypass-cap ring sits 1.9 mm inboard of the LED line,
   - back side: battery clip 8×8 back pad (|x|,|y| ≤ 4.2 keepout), cell
     disc r 10.45, SW2 body + NPTH pegs on the left straight,
   - any pre-placed via must be checked against BOTH sides' copper and
     the clip hole rule (|x| or |y| > 4.35, r > 4.6) — programmatically,
     never by eye.
5. **route.py.** I2C is slow; freerouting should handle it with no help.
   If anything needs locked copper, obey the freerouting rules below and
   verify with `scripts/check_locked_copper.py` (edit its chain lists;
   run against the pre-route board save, not the routed output — the
   shipped chains are the USB pair as a worked example).
6. **Rebuild + review.** `python3 build.py`, watch the dashboard. If
   route/finish doesn't converge in 6 attempts, read the residual
   `no candidate` edges in the log — deterministic repeats mean a walled
   pocket that needs a scanned via (`safe_via_spot`) or a locked link,
   not more retries.
7. **Firmware note (out of scope for the board):** INT1 wake +
   I2C at 400 kHz; LSM6DS3TR-C idles ~µA in accel low-power mode.

## Hard-won constraints (do not relearn these)

Full details live in auto-memory (`freerouting-integration`,
`simple-earring-framework`, `pcbnew-scripting-gotchas`) and in code
comments next to the geometry they protect. Headlines:

- **freerouting v2.2.4**: fixed wires that *start on a component pad*
  hang it pre-pass; some fixed-track sets crash its SES writer into a
  silent restart loop (log: repeated startup banners in
  `/tmp/freerouting/freerouting.log`); a locked wire with a real
  clearance violation burns the whole 900 s budget. Vias are always
  safe to pre-place. Anything else goes post-route, gated on
  `Obstacles.clear_seg`.
- **kicad-cli GLB export** prefers `.step` over `.wrl` under
  `--subst-models`, and the STEP path mis-transforms back-side
  footprints. WRL-only (with transforms baked in-file, footprint
  offset/rotate fields kept trivial) is the safe convention.
- **J1's pad row + tie pads + shell legs** seal the back layer at the
  tip; the tie pads (A4B9 etc.) are 0.7×1.4 mm custom-shape pads that
  report 0.01 mm via GetSize() — use GetEffectivePolygon.
- **LED grid**: SW2's pegs need the 1.5 mm LED-bracketing clearance
  (chain re-pitches around the anchor LED4 at S=7.75 in place.py);
  LED courtyards need ≥2.27 mm spacing at the 45° chain rotation.
- `pcbnew` python: `fp.Models()` yields copies — mutate via
  clear()+push_back; `Delete` not `Remove`; see gotchas memory.
